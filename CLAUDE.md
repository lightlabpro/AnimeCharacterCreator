# Anime Character Creator: notes for Claude Code

- This repo is shared with a second Claude (the normal chat) that builds the Blender asset library. Use the `creator-bridge` skill: read `bridge/LEARNINGS.md` and `bridge/inbox-for-code.md` at session start, log what you learn at the end, and keep `knowledge/expected-contract.json` current (`python3 bridge/tools/export_contract.py`) after changing controls, performance keys or the rig code.
- Check before pushing: `npm run typecheck`, `npm test`, `npm run build`. Python needs only numpy and Pillow for the validator.
- Develop on the branch the session names. Do not open a PR unless asked. Never commit tokens.
- Changing the asset contract (names in `docs/CLAUDE_BUILD_PROMPT.md`) needs an inbox item to the chat first.
- Head proportions are tested against `knowledge/head-targets.json` (`tests/headShape.test.ts`). To retune the ellipsoid head run `npx vite-node scripts/fit_head.ts`. Python tests: `python3 -m unittest discover -s tests/py`.
- Skills live in `.claude/skills/`. After editing one run `python3 bridge/tools/package_skills.py`, then `python3 scripts/validate_skills.py` (checks frontmatter, links, script paths, zip drift and the contract). CI runs both plus the Python tests.
- Validator exit codes: 0 pass, 12 failed, 13 unknown (not measured, never a pass), 2 usage.
- The validator's floors are calibrated on real images (`tests/fixtures/validator`, `knowledge/validator-calibration.json`). If you change a metric or a floor, re-run `python3 -m unittest discover -s tests/py` and update the calibration file; `tests/py/test_real_images.py` pins them.
- To validate the creator's own renders: start `npx vite --port 5173`, run `node scripts/capture_views.cjs --out work/app` (Playwright, headless Chromium, transparent fixed views via `window.creator.captureViews`; `?capture` enables the hook in built versions), then feed the PNGs to `validate.py measure`. The face reference must be an isolated character crop, e.g. `tests/fixtures/validator/mhs3.png`.
- The built-in procedural bodies are **placeholders**; the real models come from the Blender asset library the chat builds. Prioritise the import pipeline: `check_pack.py` (library-pack-check skill) validates exports, `node scripts/e2e_pack.cjs` proves import, sliders, performance keys and socket attachment in the real app, `tests/py/test_e2e_pack.py` wraps it. Do not tune the placeholder art.
- A loaded body pack hides all procedural body meshes (face parts and hair included) and moves pack-backed equipment onto the pack's own `SOC-` nodes (`moveEquipToPackSockets`).
